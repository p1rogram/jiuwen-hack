| 2026-11-07 | Цена задачи оценивается по готовому промпту: вход = символы / символов-на-токен по типу, выход — среднее и p90 по типу, + вероятность повтора; параметры калибруются по журналам (`tools/calibrate_cost`) | Вход известен до вызова почти точно (у search это 2/3 цены); на отложенной половине 120 задач WAPE 0.23 против 1.01 у констант по типу | GBDT по признакам — данных пока сотня задач, отложено до этапа 2 |
| 2026-11-07 | Символов на токен — отдельно по типу, без свободного члена | Одна прямая на все типы дала сдвиг −175 токенов: search ~2.8 симв/ток, math ~3.9 | Общая прямая `a·chars + b` |
| 2026-11-07 | Два прохода: детектор и промпты всех задач до первого вызова LLM, потом выбор | Без промпта цена входа неизвестна, а порядок нужен до старта | Оценивать без промпта по типу — ошибка в разы на search/coding |
| 2026-11-07 | Допуск задачи — по `high` (p90 выхода) с резервом на задачи в работе; порядок — по `mean` | Перерасход обрывает весь запуск; симуляция: перерасход в 1 сценарии из 24 против 18 у старого допуска, баллов не меньше | p95: 0 перерасходов, но −15 баллов при бюджете 50 %; допуск по `mean` без резерва — старое поведение |
| 2026-11-07 | Поправка во время прогона — среднее с априорным весом 5 псевдо-наблюдений | Скрытый набор может отличаться от наших шаблонов; вес 5 не даёт одной задаче развернуть оценку | Без поправки; скользящее среднее без априорного веса |
| 2026-11-07 | Задача, не прошедшая допуск, откладывается до второго прохода после всех остальных; `skipped_budget` — только после него | Резервы задач в работе стоят по `high`, факт обычно меньше: симуляция +13 баллов при бюджете 50 % | Окончательный пропуск при первой неудаче (ревью: занижает баллы) |
| 2026-11-07 | После провала этапа 1 ветка выбирается по EMV = `p_feasible · p · reward − λ · цена`; λ — выгода на токен первой задачи вне жадного рюкзака оставшихся (0, если бюджета хватает на все) | Штрафа за неверный ответ нет: при свободном бюджете выгодна любая ветка с `p > 0`, при тесном — токен стоит баллов другой задачи; постоянная цена токена ошибалась бы в обе стороны | Безусловный повтор и эскалация; постоянный λ из конфига |
| 2026-11-07 | Ветка допускается, только если её `high` помещается в резерв; повторный резерв задачи заменяет её прежний | Перерасход обрывает весь запуск; прежний резерв задачи — оценка этапа 1, который уже оплачен | Без резерва для веток — этап 2 (high ≈ 5 тыс.) мог бы вытеснить бюджет параллельных задач |
| 2026-11-07 | Развилки обходит `TaskPipeline`, считает — `DecisionPolicy` (без ввода-вывода); `Harness` только даёт λ | Лимит размера классов и тесты политики без LLM | Логика веток в `Harness` или в `Stage1Solver` |
| 2026-11-07 | Этап 2 — свой цикл через `LlmGateway`, не `ReActAgent` openjiuwen; инструмент `run` = Python-скрипт в папке задачи, ответ — строка `FINAL:` | Тот же учёт, семафор и журнал, стоп по бюджету до каждого вызова; скрипт одинаково работает в Windows и в контейнере, без shell | `ReActAgent` — нет стопа по бюджету задачи; shell-команда — `python3` в Windows указывает на заглушку Store |
