# Удобная консоль харнесса

## Зачем
Сейчас во время прогона консоль бесполезна. stdout забивает openjiuwen: в run17 — 889 строк и 2 МБ. Из них 865 —
служебная JSON-запись на каждый вызов модели, 3 — ошибки 429, в каждую из которых вложен весь промпт. Наши строки по
задачам печатаются только в самом конце. Не видно, сколько задач осталось, сколько бюджета потрачено и сколько
отложено в резерв, какую ветку выбрала политика. Нужно видеть прогон, пока он идёт. Решение задач и расход токенов
от этого меняться не должны.

## Критерии готовности (проверяемые)
- [x] Консоль openjiuwen выключена: прогон харнесса не печатает в stdout ни одной строки openjiuwen, ни INFO, ни
      ERROR. Его файловый журнал (`./logs/logs/run/jiuwen.log` от текущей папки) остаётся как сейчас. Включается до первого
      импорта `openjiuwen.core.foundation.llm` через `configure_log_config`. Предупреждения `SyntaxWarning` из пакета
      `pysbd` при импорте не печатаются.
- [x] Живая строка прогресса в stderr: задачи сделано / в работе / осталось, бюджет потрачено / в резерве / всего,
      текущее λ, паузы 429. Пример:
      `[ 37/163 | в работе 3 | осталось 123 ]  токены 21 480 / резерв 2 950 / 100 000  λ 0  429: 1`.
      Обновляется не чаще раза в `console.refresh_sec`.
- [x] Строка на каждую развилку политики, в момент решения. Формат —
      `coding_0396: tests_fail → stage2 (EMV 1,5 > retry 1,0)`: выбранная ветка с EMV, затем лучшая отвергнутая. Ветка,
      не поместившаяся в резерв, помечена `не влезает`; если её EMV больше выбранной, вместо `>` — `;`
      (`→ retry (EMV 1,0; stage2 1,5 не влезает)`). Если выбор был из одной ветки, выводится
      `→ stage2 (EMV 1,5, одна ветка)`; стоп — `→ stop (лучшая stage2 EMV 1,5 не влезает)`.
- [x] Строка по каждой задаче в момент её завершения: статус, цена, ответ, `stage2` с причиной стопа. Итоговая сводка
      в конце: по статусам, потрачено из бюджета, спасено этапом 2. Конечная печать результатов в `main()` заменяется
      этой сводкой.
- [x] 429 — короткая строка `429: пауза 61 с (задача search_0122)` из нашего события `rate_limit`, без промпта.
- [x] Если stderr — не терминал (перенаправлен в файл, логи Docker), `\r` не используется. Вместо живой строки —
      обычная строка прогресса раз в `console.plain_every_sec`; строки задач и развилок — как в терминале.
- [x] Тексты и форматы строк, интервалы и включение лежат в `config/console.json`, не литералами в коде.
- Ключевой критерий парой (тесты, `tests/test_console.py`):
  - должно пройти: прогон поддельного `Harness` (как в `tests/test_harness_budget.py`) с включённой консолью даёт
    те же записи журнала задач (статусы, ответы, цены) и тот же `ledger.spent`, что без консоли;
  - должно быть отклонено (то есть не сломать прогон): поток консоли бросает `OSError` / `UnicodeEncodeError` на каждой
    записи. Прогон всё равно завершается с теми же записями, а консоль выключается после первой ошибки.

## Не входит (non-goals)
- HTML-страница или веб-интерфейс по журналу — отдельная фича, если понадобится для демонстрации.
- Цветной вывод, библиотеки `rich` / `tqdm` (новые зависимости в `requirements.lock`).
- Интерактивность: пауза, отмена, смена бюджета во время прогона.
- Показ полного дерева задачи (все ветки с p и ценой) в консоли — оно остаётся в журнале и в `tools/gen/report`.
- Изменение решений политики, порядка задач, промптов, учёта токенов.

## Ограничения
- Безопасность/данные: консоль не печатает промпты, ключи и содержимое задач. Только `task_id`, статус, ответ
  (как сейчас), цены, λ. Файловый журнал openjiuwen остаётся на месте и содержит промпты, как и сейчас.
- Архитектура:
  - новый модуль `harness/console.py` (`ConsoleView`) — подписчик событий журнала: счётчики, поток, живая строка;
    строки из событий собирает `harness/console_format.py` (`LineFormat`, без ввода-вывода);
  - `harness/jiuwen_logging.py` — тихая настройка openjiuwen, импортируется первым;
  - `JsonlLog` получает список подписчиков; `TaskPipeline` пишет событие `decision`, `Harness` — `run_start` и
    `task_start`;
  - консоль только читает события и `BudgetLedger` (потрачено, резерв), сама ничего не меняет. Новых `*Manager` нет.
- Контент: форматы строк — `config/console.json`.
- Внешние контракты:
  - `answer.txt`, `OUT` и коды выхода не меняются;
  - в журнале JSONL появляются записи с новыми `kind` (`run_start`, `task_start`, `decision`). Это совместимо:
    `tools/cost_data`, `calibrate_success`, `gen/report` фильтруют по `kind == "task"` / `"llm_call"`
    (`tools/cost_data.py:65`, `tools/gen/report.py:21`, `tools/calibrate_success.py:61`);
  - stdout становится пустым. У организаторов требований к stdout нет (vault `Task.md`, `Conference-2026-11.md`).

## Пре-мортем
- Допущение о коде (проверено 2026-11-07):
  - шум печатает stdout-хендлер openjiuwen (`core/common/logging/default/default_impl.py:350`), уровень INFO по
    умолчанию (`default/constant.py`);
  - опыт в `D:/claude-tmp/jw-logtest`: `configure_log_config({... "level": "WARNING", "output": ["console"]})` до
    импорта `Model` → stdout 0 строк против 3; с обёрткой `{"logging": ...}` — `ValidationError`, ключи передаются
    напрямую;
  - нужное для прогресса уже есть: 429 — событие `rate_limit` (`harness/llm.py:71`), развилка —
    `harness/pipeline.py:45`, резерв = `total − spent − available` в `BudgetLedger`.
- Частичный сбой:
  - запись в консоль упала (закрытый поток, кодировка cp1251 без «→») — консоль глушит ошибку и выключается, задачи
    идут дальше;
  - исключение внутри `Harness.run` — живая строка снимается в `finally`, чтобы трассировка не склеилась с `\r`;
  - задача упала с `error` / `budget_exhausted` — её строка печатается как обычно.
- Одновременность: события идут из корутин одного потока, без гонок. Фаза A (`to_thread` детектора) ничего не пишет
  в журнал. `JsonlLog` уже под `threading.Lock` — подписчиков зовём под тем же замком, порядок строк = порядок в
  журнале.
- Влияние на выполнение: консоль не вызывает модель, не трогает бюджет и порядок задач. Таймер обновления — одна
  корутина с `sleep(refresh_sec)`; её стоимость ничтожна против секундных вызовов LLM. Это проверяет тест пары.
- Источник ожидаемых значений в тестах: эта spec (формат строк, пара) и `Decision` из `harness/decision.py`.
- Не заметит verify.sh: как это выглядит в настоящем терминале Windows (PowerShell, кодировка) и в `docker logs`.
  Проверка вручную на 8 примерах (~2 тыс. токенов) в терминале и с перенаправлением в файл.

## Открытые вопросы
- Ошибки openjiuwen уровня ERROR, кроме 429, тоже скрыть с консоли? Предлагаю да: наш шлюз и так превращает их в
  статус `error` задачи с текстом исключения, а целиком они остаются в файле openjiuwen. Иначе вернётся шум с промптами.
- Десятичная запятая и русские подписи в строках (`EMV 1,5`, `в работе`), как в примере? Или латиница, чтобы было
  безопасно в любой кодировке консоли? Предлагаю русский, а при ошибке кодировки — замену символа, а не выключение.
