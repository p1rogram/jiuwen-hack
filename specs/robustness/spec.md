# Устойчивость харнесса перед сдачей

## Зачем
Ревью 2026-11-09 (arch-reviewer, пункты проверены по коду): сбой на одной задаче или одном файле может оборвать весь
прогон у жюри или потерять задачу целиком. Баллы теряются на любой такой мелочи, а на скрытом наборе её не увидеть.
Жюри должно получить `answer.txt` и `OUT` по всем решённым задачам, что бы ни случилось с остальными.

## Критерии готовности (проверяемые)
### 1. Запись ответов не роняет прогон (`harness/results.py`, `run_agent.py`)
- [x] `ResultsWriter.record` при ошибке записи `answer.txt` (нет прав, нет папки, нет места) не бросает исключение:
      ответ всё равно попадает в `OUT`, ошибка возвращается и пишется в запись задачи журнала (`write_error`).
- [x] Ошибка записи `OUT` не мешает записать `answer.txt`; ошибка `discard` не бросает исключение.
- [x] `OUT` существует с первой секунды прогона: при создании `ResultsWriter` пишется `{}`. Нельзя записать — строка
      в stderr, прогон идёт дальше.
- Ключевой критерий парой (тест `tests/test_results.py`):
  - должно пройти: папка задачи недоступна для записи → `record` без исключения, в `OUT` есть ответ этой задачи,
    вторая задача пишется как обычно;
  - должно быть отклонено: задача без принятого ответа — в `OUT` её нет, `answer.txt` нет (как сейчас, обзор
    организаторов 07.11: «невыполнимая — не создавайте файл»).

### 2. Загрузка задач (`harness/tasks.py`)
- [x] Битый `task.json` (невалидный JSON, не UTF-8, не объект) пропускается со строкой в stderr; остальные задачи
      загружаются.
- [x] Нет `reward` или он не число → `reward` = 1.0 (а не 0: при 0 EMV ветки ≤ 0 и задача не получает ни повтора,
      ни этапа 2, при λ > 0 — `skipped_low_value`).
- Парой (тест, новый `tests/test_tasks.py`): папка с одной битой и одной нормальной задачей → загружена одна;
  задача без `reward` → 1.0; задача с явным `"reward": 0` → остаётся 0 (близкий случай, который подменять нельзя).

### 3. Сбой детектора невыполнимых (`run_agent.py`, `_prepare`)
- [x] Исключение в `FeasibilityDetector.check` → сигналов нет, задача решается как обычно; в журнал — событие
      `detector_error` с `task_id`.
- Парой (тест): детектор бросает → задача доходит до решения; `Stage1Prompt.build` бросает → по-прежнему
  `status: error` (этот случай не глушим — без сообщения решать нечего).

### 4. Повтор при сетевых сбоях и 5xx (`harness/llm.py`, `config/harness.json`)
- [x] Обрыв соединения или ответ 5xx → до `stage1.network_retries` (по умолчанию 2) повторов с паузой
      `network_retry_wait_sec` (по умолчанию 5 с); каждая пауза — событие журнала `net_retry`. Токены не списываются:
      ответа с `usage` нет. Признаки ошибки (имена исключений openai SDK) — в `config/harness.json`, не в коде.
- [x] 429 — как сейчас (`rate_limit_*`); 4xx кроме 429 — без повтора.
- Парой (тест `tests/test_llm_usage.py`, фейковый сервер): первый ответ 500, второй 200 → `ask` возвращает ответ,
  списан один вызов; ответ 400 → исключение сразу, сервер получил один запрос.

### 5. Документы
- [x] `docs/DECISIONS.md`: принятый риск песочницы — скрипт модели может прочитать ключ из `/proc/1/environ` и писать
      в папки других задач; почему не закрываем до сдачи; что сделано (`LLM_API_KEY` убран из окружения скрипта).
- [x] `docs/ARCHITECTURE.md`, раздел «Бюджеты»: убрать ссылку на `.claude/limits.conf` (его нет в репо).
- [x] README: строка про `OUT` = `{}` при старте и про пропуск битых `task.json`.

### 6. Проверка целиком

## Не входит (non-goals)
- Полная песочница скриптов (отдельный пользователь, seccomp, перезапуск без ключа через `execve`) — риск принят.
- Пауза 429 больше 30 с: по журналам 34 события 429, ни одной задачи не потеряно.
- Hard-пропуск невыполнимых, дубликаты `task_id`, сокращение README — без изменений.
- Сохранение частичного результата при `SIGTERM`/таймауте жюри — `OUT` и так пишется после каждой задачи.

## Ограничения
- Безопасность/данные: `.env` не читать; прогоны — только на копиях задач, прокси ≤ 3 запросов.
- Архитектура: меняются `harness/results.py`, `harness/tasks.py`, `harness/llm.py`, `run_agent.py` (`_prepare`,
  `_solve_one`), `config/harness.json`; новых классов нет. `run_agent.py` — 201 строка, рост ≈ 10.
- Контент: число повторов, пауза, признаки сетевой ошибки — `config/harness.json`.
- Внешние контракты: формат `OUT` и `answer.txt` не меняется; новое — `OUT` = `{}` до первого ответа (совместимо:
  валидный JSON того же вида). Журнал: новые поля `write_error`, `detector_error`, событие `net_retry` — `ConsoleView`
  незнакомые события пропускает (`getattr(self, f"_on_{kind}", None)`), `tools/cost_data` читает только `llm_call`/`task`.

## Пре-мортем
- Допущение о коде (проверено Read 2026-11-09): `writer.record`/`discard` вызываются после `try` в `_solve_one`
  (`run_agent.py:167`); `OUT` пишется только в `record` (`harness/results.py:32`); `load_tasks` без `try`
  (`harness/tasks.py:27`); `reward` по умолчанию 0 (`harness/tasks.py:31`), `emv > 0` (`harness/decision.py:113`);
  ошибка детектора уходит в общий `except` `_prepare` (`run_agent.py:126`); openjiuwen создаёт клиент openai с
  `max_retries=0` (`openai_model_client.py:908`) — сам вызов чата не повторяет; текст ошибки содержит имя класса
  SDK (`RateLimitError: Error code: 429` в журнале 07.11) — по нему и узнаём 5xx/обрыв.
- Частичный сбой: таймаут 180 с — не повторяем (сервер мог сгенерировать и посчитать токены у себя; повтор удвоит
  расход вне нашего учёта) — см. открытый вопрос 1. Сервер лежит долго → 2 повтора × 5 с на задачу, потом `error`,
  как сейчас; на 100 задачах ≤ 17 мин ожидания при общем падении — приемлемо.
- Одновременность: `record` зовут параллельные корутины одного потока — `_answers` и `_flush` под общим замком,
  `OUT` пишется через `tmp` + `os.replace`; начальный `{}` пишется до запуска задач.
- Источник ожидаемых значений в тестах: эта spec и обзор организаторов 07.11 (`answer.txt`, «невыполнимая — не
  создавайте файл»); формат ошибки 5xx — имена классов openai SDK (`InternalServerError`, `APIConnectionError`).
- Не заметит verify.sh: точный текст ошибки 5xx/обрыва от прокси жюри (тест — на фейковом сервере через тот же
  openjiuwen, текст строит SDK); права на запись в `/data/tasks` у жюри — проверка образом на примерах.
